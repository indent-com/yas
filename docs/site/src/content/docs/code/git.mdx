`yas git` reads git repositories on the machine that runs the server. The server reads the
repository itself, so reads work on a machine without a `git` binary. You get status, history,
diffs, file contents at any revision, blame, reflogs, and fetch. Every command is read-only except
`fetch`, and every command works against a remote with `--on`.

## Point at a repository

Run `yas git` inside a worktree, or pass the repository's path with `--repo`:

```bash
cd ~/demo
yas git log
```

```text
0c3c8e95 Dev <dev@example.com> Document cargo run
fceee4bf Dev <dev@example.com> Rename greet module file
2391d6c1 Dev <dev@example.com> Shorten greeting
8c33ec5b Dev <dev@example.com> Initial commit
```

`--repo` defaults to `.`. A relative `--repo` resolves against your shell's current directory, as
`--root` does for `yas fs` and `yas lsp`. A subdirectory of a worktree selects the repository that
contains it.

To find repositories in a directory and below it, use `discover`:

```bash
cd ~
yas git discover
```

```text
/home/you/demo	/home/you/demo/.git
```

Each line is the worktree and its git directory, separated by a tab. `discover` never searches
above its path, so it prints nothing when run from inside a worktree. `--depth` sets how deep to
search (4 by default), `--nested` looks inside repositories it finds, and `--bare` reports bare
repositories.

## History

`log` prints the abbreviated commit id, the author, and the subject, newest first. It takes a
revision or range and an optional path after `--`:

```bash
yas git log main..feature
yas git log --follow -- src/greeting.rs
```

```text
41d0ab11 Dev <dev@example.com> Add bye
fceee4bf Dev <dev@example.com> Rename greet module file
2391d6c1 Dev <dev@example.com> Shorten greeting
8c33ec5b Dev <dev@example.com> Initial commit
```

The first line is the output of the first command: the one commit on `feature` that `main` lacks. The other lines come from the second command, which follows `src/greeting.rs` back through the
commit that renamed it from `src/greet.rs`.

- `-n` sets the number of commits, 20 by default.
- `--first-parent`, `--topo`, and `--full-message` work as in git.
- `--watch` reprints the page whenever the refs at its ends move.
- `--json` prints one commit per line, with `oid`, `parents`, `tree`, `author`, `committer`, and
  `message`. Each person has `name`, `email`, `time` in Unix seconds, and `tz`.

`reflog` prints a ref's history. `merge-base` prints the best common ancestor of two or more
revisions:

```bash
yas git merge-base main feature
```

```text
2391d6c17fa89b7a67ec859f0969a807f9dbfb54
```

## Diffs

With no revision, `diff` compares the worktree to the index:

```bash
yas git diff
yas git diff --staged
```

```text
A	Cargo.lock
M	src/main.rs
M	README.md
```

Each line is a status letter and a path. `A` is added, `M` modified, `D` deleted, and `R` renamed,
shown as `old -> new`. Untracked files appear as `A`. The first two lines come from the worktree.
The last line is the staged change that `--staged` reports.

- One revision compares it with the worktree, or with the index when you add `--staged`.
- Two revisions, or `A..B`, compare two commits. `A...B` compares `B` with the point where it forked
  from `A`.
- `--merge-base REV` compares the worktree with the point where `REV` forked.
- A path after `--` limits the diff to that path.
- `-p` prints unified hunks, with or without revisions. `--binary` adds binary patches that `git apply --binary` accepts.
- `--json` prints one object per file.

```bash
yas git diff -p -- src/main.rs
```

```text
diff --git a/src/main.rs b/src/main.rs
index 46be10757c49f508485a736978767b12ae41e82c..8c2803c3062ca86662531c06b7fb562819d01e35 100644
--- a/src/main.rs
+++ b/src/main.rs
@@ -3,5 +3,5 @@ mod greet;

 fn main() {
     let name = "world";
-    println!("{}", greet::hello(name));
+    println!("{}", greet::hello(nme));
 }
```

The patch above compares the worktree with the index. The next one compares `feature` with the
point where it forked from `main`:

```bash
yas git diff main...feature -p
```

```text
diff --git a/src/greet.rs b/src/greet.rs
index 06958d979f91fa2ba47c079c1735be08f437bb09..79392ec15308501aa14d6be44ad4e0a41c729f0d 100644
--- a/src/greet.rs
+++ b/src/greet.rs
@@ -2,3 +2,6 @@
 pub fn hello(name: &str) -> String {
     format!("Hi, {name}!")
 }
+pub fn bye(name: &str) -> String {
+    format!("Bye, {name}!")
+}
```

## Status

`status` prints the branch and the working-tree state:

```bash
yas git status
```

```text
on main
M  README.md
?? Cargo.lock
 M src/main.rs
!! target/CACHEDIR.TAG
```

The two columns before each path are the staged and unstaged state, as in `git status --short`.
`??` marks an untracked file and `!!` an ignored one. A clean worktree prints `clean` after the
branch line.

- `--watch` prints the same state first, then reprints it whenever the branch or the worktree
  changes.
- `--json` prints each state as an object with `head`, `oid`, `ahead`, `behind`, `stashes`, and a
  `status` list. Each status entry has `path`, `old_path`, `staged`, and `unstaged`.

## Commits, files, trees, and blame

`show REV` prints the commit object: the tree, the parents, the author and committer with Unix time
and time zone, a blank line, and the message:

```bash
yas git show HEAD
```

```text
tree 817cc7b4108c2bdcd90d429afbcf9b40aee4085a
parent fceee4bf5854eed63962cea9fde20ab32aef566f
author Dev <dev@example.com> 1788602400 +0000
committer Dev <dev@example.com> 1788602400 +0000

Document cargo run
```

`show REV:PATH` prints a file's bytes at a revision. `:PATH` reads from `HEAD`:

```bash
yas git show v0.1:src/greet.rs
```

```text
/// Build a greeting for `name`.
pub fn hello(name: &str) -> String {
    format!("Hi, {name}!")
}
```

When `PATH` is a directory, `show` lists it like `ls-tree`. `REV:` lists the root tree:

```bash
yas git show HEAD:src
```

```text
100644 blob 06958d979f91fa2ba47c079c1735be08f437bb09	greeting.rs
100644 blob 46be10757c49f508485a736978767b12ae41e82c	main.rs
```

The columns are the mode, the object type, the object id, and the name. `ls-tree` prints the same
format, and `ls-files` lists the index:

```bash
yas git ls-tree HEAD
```

```text
100644 blob ea8c4bf7f35f6f77f75d92ad8ce8349f6e81ddba	.gitignore
100644 blob cd86e21f9bab369d39886d5c18d48fa5336a9cc5	Cargo.toml
100644 blob b9f825a714befcd2030f9879b21817a680c055b4	README.md
040000 tree 0bec2fddf074f78930df0912c033724fa804802d	src
```

`blame` prints each commit and the line range it last touched:

```bash
yas git blame src/greeting.rs
```

```text
fceee4bf5854eed63962cea9fde20ab32aef566f 1-4
```

`--rev` blames from another revision, `-M` follows renames, and `--start` with `--lines` limits the
range.

## Fetch

`fetch` downloads from a remote named in the repository's config, `origin` by default. It runs the
server machine's `git` binary with prompts turned off, so the remote must not need an interactive
password. It prints each updated ref and the result:

```bash
yas git fetch
```

```text
refs/remotes/origin/main	Ok
refs/remotes/origin/topic	Ok
```

A fetch with nothing new prints nothing. `--prune` deletes remote-tracking refs the remote no longer
has, and `--timeout` gives up after that many seconds, 120 by default.

<Aside type="note" title="Limits">

- `REV` in `show` names a commit. A raw tree or blob id fails with `Invalid`. Reach trees and blobs
  through `REV:PATH`.
- The server disables `yas git` with `YAS_GIT=0` and `fetch` alone with `YAS_GIT_FETCH=0`. Size
  limits such as `YAS_GIT_BLOB_MAX` are listed in
  [Environment variables](/reference/environment-variables).

</Aside>

Full flags are in the [`yas git` reference](/reference/cli/git).
