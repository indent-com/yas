A server-side program can use `@yas-run/core` to drive a yas server on the same machine: start
terminals, send input, and wait for commands to exit. It connects over the server's Unix socket,
uses the same `YasWorkspace` API as the browser components, and needs no edge or passphrase. The
Node, Bun, and Deno pieces live under the `@yas-run/core/node` subpath so browser bundles never
import `node:net`.

## Install

```bash
npm install @yas-run/core @yas-run/browser
```

`@yas-run/browser` is the WebAssembly module the workspace uses for terminal state. `loadYasWasm()`
from `@yas-run/core/node` reads its `.wasm` file from disk and initializes it, so you never handle
the bytes yourself. Pass a path to `loadYasWasm(path)` to load the file from somewhere else.

The packages are plain ES modules and load in Node without a bundler.

## Run a command and read its exit status

Save this as `run-command.mjs`. It starts one command in a new terminal on the server named by
`YAS_SOCK`, waits for it to exit, and exits with the same status.

```js
import {
  YasWorkspace,
  exitCodeFromStatus,
  formatExitStatus,
  nullLogger,
} from "@yas-run/core";
import { NodeUnixSocketTransport, loadYasWasm } from "@yas-run/core/node";

const socketPath = process.env.YAS_SOCK;
if (!socketPath) throw new Error("set YAS_SOCK to the server's Unix socket");

const workspace = new YasWorkspace({
  wasm: await loadYasWasm(),
  logger: nullLogger,
  connections: [
    { id: "default", transport: new NodeUnixSocketTransport(socketPath) },
  ],
});

await new Promise((resolve) => {
  const check = () => {
    if (!workspace.getSnapshot().ready) return;
    unsubscribe();
    resolve();
  };
  const unsubscribe = workspace.subscribe(check);
  check();
});

const session = await workspace.createSession({
  connectionId: "default",
  rows: 24,
  cols: 80,
  command: process.argv[2] ?? "echo hello; exit 3",
});
console.log("started", session.id);

const exited = await workspace.awaitSessionExit(session.id, {
  timeoutMs: 30_000,
});
console.log("status", exited.exitStatus, formatExitStatus(exited.exitStatus));
console.log("exit code", exitCodeFromStatus(exited.exitStatus));

workspace.dispose();
process.exit(exitCodeFromStatus(exited.exitStatus));
```

- `NodeUnixSocketTransport` connects to the server's socket. `BunUnixSocketTransport` and
  `DenoUnixSocketTransport` take the same path and use the runtime's own socket API. Deno needs
  `--allow-read --allow-write` for the socket path.
- `nullLogger` silences the workspace. Leave `logger` out to print lifecycle events to the console.
- `workspace.getSnapshot().ready` turns true once the server's HELLO has arrived. `createSession`
  rejects with `Terminal family is not ready or was not negotiated` before that.
- `createSession` returns a snapshot of the session at creation. Read later state with
  `workspace.getSession(id)`, `awaitSessionExit`, or `subscribe`.
- `command` runs through the server's login shell. Pass `argv: ["prog", "arg"]` instead to start a
  program directly.

Run it against a private server:

```bash
D=$(mktemp -d); yas server --socket "$D/yas.sock" --name docs &
export YAS_SOCK="$D/yas.sock"
node run-command.mjs; echo "shell exit: $?"
node run-command.mjs 'kill -9 $$'; echo "shell exit: $?"
yas terminal list
yas quit
```

```text

exit code 3

started default:terminal:2

ID	TAG	TITLE	COMMAND	CWD	STATUS

```

The session ID has the form `<connection>:terminal:<pty>`. The terminals stay on the server after
your program exits, as the `yas terminal list` output shows.

## Exit status

When a terminal's process ends, its `YasSession.state` becomes `"exited"` and `exitStatus` holds the
raw status from the server. While the process runs, `exitStatus` is `null`.

- `0` or more: the process exited normally with that code.
- Below `0`: a signal ended the process; the value is the negated signal number.
- `EXIT_STATUS_UNKNOWN` (`-2147483648`): the status has not been collected.

Two helpers match the `yas` CLI:

- `exitCodeFromStatus(status)` returns a shell-style code: the code itself, `128 + signal` for a
  signal, or `1` when unknown.
- `formatExitStatus(status)` returns `exited(<code>)`, `signal(<n>)`, or `exited` when unknown.

To react to exits without awaiting one terminal, subscribe to the workspace:

```js
workspace.subscribe(() => {
  for (const s of workspace.getSnapshot().sessions) {
    if (s.state === "exited" && s.exitStatus !== null) {
      console.log(s.id, "exited with code", exitCodeFromStatus(s.exitStatus));
    }
  }
});
```

## Other operations

The workspace here is the same object the browser components use. `sendInput(id, bytes)`,
`resizeSession(id, rows, cols)`, `killSession(id, signal)`, `closeSession(id)`, and
`search(query)` all work from a script. See
[Workspace operations](/embedding/react#workspace-operations).

For one-off scripting from a shell, the `yas` CLI does the same work without code. See
[Controlling terminals](/terminals/controlling-terminals).
